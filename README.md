# وجباتي - Wajbati

التحديثات الحالية وإعدادات تفعيل الإشعارات والأمان والنسخ الاحتياطي موثقة في [docs/UPDATES.md](docs/UPDATES.md).

لوحة الكافيتريا تحتوي أقسامًا مستقلة للطلبات والمنيو وماسح QR والتقارير، مع تنقل جانبي على الكمبيوتر وتنقل سفلي على الهاتف. التقارير تدعم اليوم وآخر 7 أيام وهذا الشهر وفترة مخصصة، وتحسب المبيعات بتاريخ التسليم.

تطبيق Flutter لطلب الوجبات من كافيتريات الجامعة: واجهة للطالب ولوحة تحكم لمسؤول الكافيتريا.

## التشغيل

التطبيق يحتاج السيرفر (FastAPI) في مجلد [backend/](backend/README.md).

```bash
# 1) السيرفر
cd backend
uv sync
uv run uvicorn project.main:app --host 0.0.0.0 --port 8001

# 2) التطبيق (في نافذة أخرى)
flutter pub get
flutter run -d chrome
```

- عنوان السيرفر الافتراضي في التطبيق: `http://localhost:8001` (ومحاكي أندرويد: `http://10.0.2.2:8001`).
- لتغييره: زر "السيرفر" أسفل شاشة الدخول، أو وقت التشغيل:
  `flutter run --dart-define=API_URL=http://192.168.1.10:8001`
- على هاتف حقيقي: استخدم عنوان IP للكمبيوتر، وتأكد أن الهاتف على نفس شبكة الواي فاي.

## اللغة وإدارة المنصة

- زر `English / العربية` في شاشات الدخول والواجهات الرئيسية يغيّر لغة الواجهة واتجاهها ويحفظ الاختيار. تبقى السلة والحقول المدخلة محفوظة عند التبديل.
- من شاشة الدخول اختر **إدارة المنصة**. حساب مسؤول المنصة مستقل عن حساب الطالب ورمز صاحب الكافيتريا.
- يضيف المسؤول الكافيتريا بالاسم والموقع وساعتي الفتح والإغلاق ورمز دخول لصاحبها. تظهر الكافيتريا للطلاب، ثم يدخل صاحبها بالرمز ويضيف المنيو من حسابه.
- لتجهيز مسؤول جديد من مجلد `backend`: `uv run python -m project.manage create-admin admin`. تُطلب كلمة مرور وتأكيدها دون إظهارها. لا يُنشأ حساب مسؤول بكلمة مرور افتراضية عند تشغيل السيرفر.
- لاستعادة كلمة مرور مسؤول بعد التحقق من هويته: `uv run python -m project.manage reset-password platform admin`.

## تجربة تدفق الطلب كاملاً

1. سجّل دخول طالب (حساب تجريبي: `07700000000` / `123456`) أو أنشئ حساباً.
2. اختر كافيتريا مفتوحة ← أضف أصنافاً (مع ملاحظات مثل "بدون بصل") ← السلة.
3. اختر وقت الاستلام ← اختر طريقة الدفع ← أكّد الطلب.
4. سجّل خروج، ثم من شاشة الدخول اختر "دخول مسؤول الكافيتريا" (رمز علوم حاسوب: `CS771SOL`).
5. غيّر حالة الطلب: بدء التجهيز ← جاهز للاستلام ← تم التسليم (أو امسح رمز QR الطالب).
6. ارجع لحساب الطالب: ستجد الإشعارات وتحديث الحالة، ويمكنك التقييم و"أعد الطلب".

## الحالات الأربع للطلب

| الحالة (في السيرفر والكود) | تظهر للطالب |
|---|---|
| `received` | تم استلام الطلب |
| `preparing` | قيد التحضير |
| `ready` | جاهز للاستلام |
| `delivered` | تم التسليم |

الثوابت معرّفة في `OrderStatus` داخل `lib/screens/student/student_store.dart`.

## ملاحظات

- إنشاء الحساب يحتاج الاسم ورقم الهاتف وكلمة المرور وتأكيدها؛ الرقم الجامعي غير مطلوب. خيارات إزالة المكونات خاصة بكل طبق، ومنها «بدون سكر» للشاي.

- كل البيانات (الحسابات، الطلبات، القوائم، المفضلة، الإشعارات) في السيرفر؛ السلة فقط محلية.
- تُحفظ السلة ومحاولة تأكيد الطلب محليًا لاستعادتهما بعد إغلاق التطبيق. الإلغاء والرفض متاحان قبل بدء التحضير، ويظهر السبب في تفاصيل الطلب.
- التطبيق يجلب التحديثات من السيرفر كل بضع ثوانٍ (حالة الطلب، توفر الأصناف، الإشعارات).
- تتبع الطلبات من تبويب "طلباتي" (شريط الحالات الأربع + زر "وصلت" / رمز QR على كل طلب).
- لوحة التحكم: اختيار صورة عند إضافة طبق جديد مع معاينتها وتغييرها أو إزالتها قبل الحفظ. الصورة اختيارية، وبحد أقصى 2 ميغابايت. لتغيير صورة طبق موجود اضغط على صورته. يوجد صوت تنبيه للطلبات الجديدة (زر 🔊 للكتم).
- الإشعارات تظهر داخل التطبيق. ربط Firebase في السيرفر والتطبيق موجود، وتفعيله يحتاج مشروع Firebase وإعداداته؛ راجع [دليل التحديثات](docs/UPDATES.md).
- الدفع الإلكتروني تجريبي ولا يخصم أي مبلغ (الربط الحقيقي يحتاج حساب تاجر لدى بوابة دفع).

## مكونات الأطباق وخيارات الإزالة

من «المنيو ← إضافة أو تعديل طبق»، اكتب المكونات مفصولة بفاصلة ثم اختر المكونات التي يسمح للطالب بإزالتها. يظهر للطالب وصف المكونات وخيارات الإزالة الخاصة بالطبق فقط، ويمكن اختيارها وإلغاء اختيارها دون تكرار الملاحظة.

الشاي المهيل مضبوط مبدئيًا على الشاي والماء والهيل والسكر، مع السماح بإزالة السكر فقط. المكونات المبدئية للأصناف التجريبية قابلة للتعديل من الكافيتريا حسب الوصفة الفعلية. الأطباق التي لم تُحدّد مكوناتها لا تعرض خيارات إزالة افتراضية.

## تحسينات تجربة الاستخدام

- بطاقة الطلب الحالي تعرض الحالة ووقت الاستلام وتفتح التتبع مباشرة.
- بطاقات أطباق بصور موحدة وسعر واضح وتعديل الكمية مباشرة، وشريط سلة ثابت يعرض المجموع والمتابعة.
- حذف الطبق من لوحة الكافيتريا بعد التأكيد، مع الحفاظ على تفاصيل الطلبات السابقة.
- خط Tajawal محلي، وألوان هادئة ومسافات وحواف متناسقة، وحالات تحميل ورسائل إعادة المحاولة وانتقالات قصيرة تراعي تقليل الحركة.
- الصور المعروضة هي الصور التي ترفعها الكافيتريا؛ يظهر بديل عند غياب الصورة أو تعذر تحميلها.
- الخط من [Google Fonts](https://github.com/google/fonts/tree/main/ofl/tajawal)، وترخيصه محفوظ في `assets/fonts/OFL.txt`.

## النشر

إعداد تغيير السيرفر يظهر في وضع التطوير (`flutter run`) فقط. نسخ release وprofile تخفيه وتعتمد عنوان `API_URL` المحدد عند البناء، وتتجاهل عنوان التطوير المحفوظ سابقًا. حدّد عنوان خادم الاستضافة عند بناء نسخة النشر.

ملف [render.yaml](render.yaml) جاهز: من Render اختر **New ← Blueprint** وحدد هذا المستودع،
فيُنشأ السيرفر وقاعدة بيانات PostgreSQL ومفتاح `WAJBATI_SECRET` تلقائياً.
بعدها شغّل التطبيق بعنوان السيرفر المنشور:
`flutter run --dart-define=API_URL=https://wajbati-api.onrender.com`
